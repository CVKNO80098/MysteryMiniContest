
## 二、请求是怎么走的

开发阶段浏览器只访问 5173，`/api` 由 Vite 代理到 8080：

```
浏览器
  │  GET /api/user/list
  ▼
Vite 5173  ──/api 代理──▶  Spring Boot 8080 /api/user/list
```

`vite.config.ts` 已经配好：

```ts
server: {
  port: 5173,
  proxy: {
    '/api': { target: 'http://localhost:8080', changeOrigin: true },
  },
}
```

`.env.development` 里 `VITE_API_BASE_URL=/api`；`.env.production` 里是线上后端地址。改环境变量后要重启 `npm run dev`。

## 三、跨域

后端 `common/CorsConfig.kt` 已允许跨域，前端不走代理直连 8080 时也能用：

```kotlin
@Configuration
class CorsConfig : WebMvcConfigurer {
    override fun addCorsMappings(registry: CorsRegistry) {
        registry.addMapping("/**")
            .allowedOriginPatterns("*")
            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
            .allowedHeaders("*")
            .allowCredentials(true)
            .maxAge(3600L)
    }
}
```

注意：`allowedOrigins("*")` 不能和 `allowCredentials(true)` 一起用，必须用 `allowedOriginPatterns("*")`。

> 这是演示版配置，允许任何来源。上线前要改成实际域名，并加鉴权。

## 四、统一返回格式

所有业务接口返回：

```json
{ "code": 200, "msg": "ok", "data": {} }
```

| 字段 | 说明 |
| --- | --- |
| code | 200 成功；500 业务失败（前端会直接弹 msg） |
| msg | 提示信息，成功是 `"ok"` |
| data | 业务数据，没有数据时是 `null` |

后端 `common/Result.kt`：

```kotlin
class Result<T> {
    var code: Int? = null
    var msg: String? = null
    var data: T? = null

    companion object {
        fun <T> ok(data: T): Result<T> = Result(200, "ok", data)
        fun <T> ok(): Result<T> = Result(200, "ok", null)
        fun <T> fail(msg: String): Result<T> = Result(500, msg, null)
    }
}
```

业务里直接 `throw RuntimeException("提示语")`，`common/GlobalExceptionHandler.kt` 会转成 `code=500`。

## 五、application.yaml（实际配置）

```yaml
server:
  port: 8080

spring:
  application:
    name: AngelSystem
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/campus_errand
    username: root
    password: hi58lo32
  jpa:
    hibernate:
      ddl-auto: none
    open-in-view: false
    show-sql: true
```

- `ddl-auto: none`：建表用 `sql/campus_errand.sql`，Hibernate 不自动改表。
- 日期格式由 `common/JacksonConfig.kt` 统一成 `yyyy-MM-dd HH:mm:ss`。
- 不需要 Redis/MyBatis-Plus；`pom.xml` 里没有这些依赖。

## 六、包结构

```
src/main/kotlin/com/cvkno80098/angelsystem
├── AngelSystemApplication.kt   启动类
├── common                      Result、CorsConfig、GlobalExceptionHandler、JacksonConfig
├── controller                  11 个 Controller，45 个接口
├── service                     业务接口
├── service/impl                业务实现（金额、状态、事务）
├── dao                         13 个 Repository（JpaRepository）
├── entity                      13 个实体，和表一一对应
├── dto                         接收前端参数
└── vo                          返回给前端的组合对象
    ├── OrderVO / OrderAssembler   订单 + 店铺/驿站/骑手名 + 明细
    ├── CartVO                     购物车 + 商品/店铺信息
    ├── UserVO                     用户信息（不含 password）
    └── RiderStatisticsVO / AdminStatisticsVO
```

分层约定：

| 层 | 职责 | 不该做 |
| --- | --- | --- |
| controller | 接请求、参数校验、调 service、包 Result | 不写 SQL、不写复杂业务 |
| service | 业务规则、金额、状态、事务 | 不直接操作 HttpServletRequest |
| dao | 继承 `JpaRepository` / `JpaSpecificationExecutor` | 不写业务判断 |
| entity | 和表字段一一对应 | 不塞展示字段 |
| vo | 返回给前端的组合数据 | 不直接当入参 |

## 七、登录、注册、权限

1. **没有 JWT、没有 Session、没有拦截器**。登录只查一次 `user` 表，查到返回用户信息（`UserVO`，不含密码）。
2. 前端把用户信息存在 localStorage，之后调接口把 `userId` 传过来；后端把它当“当前用户”。
3. `POST /api/user/login` 必须校验密码；失败返回 `code=500`、`msg="用户名或密码错误"`。
4. `POST /api/user/register` 的 `role` **固定为 1（顾客）**，传了其它值也忽略；骑手/管理员由 SQL 或后台初始化。
5. 权限不校验：`/api/admin/**` 谁都能调，这是演示版的边界，不是安全设计。生产版要加 JWT + 拦截器 + 角色校验。
6. 用户密码在库里是明文（示例项目），登录/列表/资料接口都返回 `UserVO`，**不要把 password 发给前端**。

## 八、下单、金额、状态（后端必须保证）

以 `OrderServiceImpl.kt` 为准：

1. **参数校验**
   - `orderType` 只能是 1/2/3；`userId` 必须存在且未禁用。
   - 外卖/小卖部：`shopId` 必填且店铺存在、营业中；`items` 不能为空。
   - 代取快递：`stationId` 必填且驿站存在、启用；`pickupCode` 必填；`packageSize` 必填。
   - `quantity` 只能 1~99；`tip >= 0`；`packageWeight >= 0`。
2. **金额**
   - 商品金额：后端按 `goods.price` 重算，不接收前端传的金额；商品必须属于该店铺、已上架、库存足够。
   - 配送费：商品单取 `shop.delivery_fee`；代取快递按包裹大小固定 2/3/4 元。
   - 合计 = 商品金额 + 配送费 + 小费，全程 `BigDecimal`。
3. **落库**
   - 同一个 `@Transactional` 里写 `orders`、`order_item`、`order_status_log`。
   - `order_item` 存商品名/图片/单价/小计的**快照**。
   - `status=1`（待接单）、`payStatus=1`（示例项目直接当已支付）。
4. **状态**
   - 在用状态：1 待接单 → 2 配送中 → 3 已完成；4 已取消；0 待支付预留。
   - 接单用 `update ... where id=? and status=1` 原子更新，防止两个骑手同时接单。
   - 合法迁移：1→4、2→3、2→4；其余拒绝。取消/关闭订单会回补库存。
   - 每次状态变更写 `order_status_log`，尽量带 `operatorId/operatorRole`。

## 十、常见问题

| 现象 | 原因 |
| --- | --- |
| 404 | Controller 路径少了 `/api`，或配了 context-path |
| 500 且控制台数据库连接失败 | `application.yaml` 密码不对，或 MySQL 没启动 |
| 返回字段全 null | 实体属性名和表字段驼峰对不上（JPA 默认 `snake_case`） |
| 日期差 8 小时 | JDBC URL 加 `serverTimezone=Asia/Shanghai`，或统一用 `LocalDateTime` |
| 加购后页面报错 | 前端把 `POST /api/cart/add` 的返回值当数组；该接口现在返回最新购物车列表 |
| 管理端下架后再也上不了架 | 管理端必须用 `/api/admin/goods/list`、`/api/admin/shop/list`（包含下架/休息） |
| 骑手统计空白 | 字段名是 `todayOrders/totalOrders`，不是 `todayOrderCount` |
| 订单列表没有店名/驿站名 | 后端 `OrderAssembler` 已补；若仍为空，确认 `shopId/stationId` 有值 |
| 保存资料后被登出 | `PUT /api/user/update` 现在返回更新后的 `UserVO`，前端直接用它刷新登录态 |
