## 一、端口与地址约定

| 服务 | 端口 | 地址 | 说明 |
| --- | --- | --- | --- |
| 前端 Vite 开发服务器 | 5173 | http://localhost:5173 | 在项目根目录执行 `npm run dev` |
| 后端 SpringBoot | 8080 | http://localhost:8080 | 不加 context-path，直接在 Controller 上写 @RequestMapping("/api/xxx") |
| MySQL | 3306 | localhost:3306 | 库名 campus_errand，账号建议 root / 123456 |

关于 Redis 单独说明一句：登录只是查一次 user 表，不做 JWT 也没有 Session，购物车、订单都直接读写 MySQL，没有任何地方用到缓存或分布式锁，所以 **pom.xml 里不要加 spring-boot-starter-data-redis，application.yml 里也不用写 redis 配置**。加了反而会因为连不上 Redis 报错。

另外，后端的 `server.servlet.context-path` **不要配**。所有路径前缀都写在 Controller 的注解里，也就是这样：

```java
@RestController
@RequestMapping("/api/user")
public class UserController {
    // 最终地址：http://localhost:8080/api/user/list
}
```

这样前端 `/api/user/list` 直接转发到 `http://localhost:8080/api/user/list`，路径一模一样，不用做任何 rewrite。

## 二、请求是怎么走的

开发阶段前端不直接访问 8080，而是访问自己的 5173，由 Vite 帮忙转发：

```
浏览器
  │  GET /api/user/list        （相对路径，不带域名）
  ▼
Vite 开发服务器  http://localhost:5173
  │  匹配到 /api 开头的请求，转发出去
  ▼
SpringBoot      http://localhost:8080/api/user/list
```

前端的接口前缀已经写在 `.env.development` 里了：

```
VITE_API_BASE_URL=/api
```

要让它生效，靠的是 `vite.config.ts` 里的代理配置。**这个项目里已经配好了，不用再改**，内容如下（贴出来是为了让后端同学知道前端请求是怎么转到 8080 的）：

```ts
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
      // 所有 /api 开头的请求都转发到后端 8080
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        // 后端路径本身就带 /api，所以不需要 rewrite
      },
    },
  },
})
```

改动 `.env.development` 或 `vite.config.ts` 之后都要重启 `npm run dev` 才生效。

## 三、跨域问题

### 3.1 为什么开发阶段其实不太会遇到跨域

浏览器只有在"页面地址"和"接口地址"的 **协议、域名、端口** 三者不完全相同时才拦截。开发阶段页面是 5173，接口请求发到的还是 5173（`/api` 是相对路径），由 Vite 在服务器之间转发，浏览器看不到 8080，所以不算跨域。

### 3.2 那为什么还要配跨域

因为这几种情况分分钟发生：

1. 前端同学把 `VITE_API_BASE_URL` 直接改成了 `http://localhost:8080/api`，绕过代理。
2. 后端同学用 Postman 或浏览器直接打开 `http://localhost:8080/api/shop/list` 测试，自己的页面里再试就报错。
3. 前端同学用 IDEA 自带的预览、或者用 `file://` 打开打包后的页面。

只要出现 `Access to XMLHttpRequest at ... has been blocked by CORS policy`，就是这个原因。**所以后端必须允许跨域，这是保底措施，配一次之后所有开发方式都能用。**

### 3.3 CorsConfig 代码（最基础的写法）

在 `common` 包里新建一个类：

```java
package com.example.campus.common;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

/**
 * 全局跨域配置。加上这个类，所有接口都允许跨域访问。
 */
@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")                 // 拦截所有路径
                .allowedOriginPatterns("*")        // 允许任何来源
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")               // 允许任何请求头
                .allowCredentials(true)            // 允许带 cookie
                .maxAge(3600);                     // 预检请求缓存 1 小时
    }
}
```

两个容易踩的坑：

| 坑 | 说明 |
| --- | --- |
| 用了 `allowedOrigins("*")` 又开了 `allowCredentials(true)` | SpringBoot 2.4 以后会直接启动报错。要用 `allowedOriginPatterns("*")`，就是上面这种写法 |
| 没放行 OPTIONS | 浏览器发 PUT、DELETE 前会先发一个 OPTIONS 预检请求，上面的 allowedMethods 已经带上了，别去掉 |

如果只想给某个 Controller 开跨域，也可以用它上面的 `@CrossOrigin` 注解：

```java
@RestController
@RequestMapping("/api/user")
@CrossOrigin   // 只让这一个 Controller 允许跨域
public class UserController {
}
```

推荐还是用上面的全局 `CorsConfig`，配一次省事。

## 四、统一返回格式

### 4.1 格式约定

所有接口都返回同一个结构，HTTP 状态码永远都是 200，业务成功失败看 `code`：

```json
{
  "code": 200,
  "msg": "ok",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | Integer | 200 表示成功，其它值表示失败（例如 500 参数错误、404 数据不存在） |
| msg | String | 提示信息，成功固定是 "ok" |
| data | 任意 | 真正的业务数据，可以是对象、数组、数字，没有数据时是 null |

举例，查询用户列表成功：

```json
{
  "code": 200,
  "msg": "ok",
  "data": [
    { "id": 1, "username": "xiaoming", "nickname": "小明", "role": 1 }
  ]
}
```

下单失败：

```json
{
  "code": 500,
  "msg": "商品库存不足",
  "data": null
}
```

前端同学只要判断 `res.data.code === 200`，然后取 `res.data.data` 就行，不用给每个接口写不同的解析逻辑。

### 4.2 Result 工具类（最简版）

放在 `common` 包下，不依赖 Lombok，直接复制能用：

```java
package com.example.campus.common;

/**
 * 统一返回结果。
 * 用法：return Result.ok(list); 或者 return Result.fail("库存不足");
 */
public class Result<T> {

    private Integer code;
    private String msg;
    private T data;

    public Result() {
    }

    public Result(Integer code, String msg, T data) {
        this.code = code;
        this.msg = msg;
        this.data = data;
    }

    /** 成功，带数据 */
    public static <T> Result<T> ok(T data) {
        return new Result<>(200, "ok", data);
    }

    /** 成功，不带数据（例如删除、修改） */
    public static <T> Result<T> ok() {
        return new Result<>(200, "ok", null);
    }

    /** 失败，只给提示信息 */
    public static <T> Result<T> fail(String msg) {
        return new Result<>(500, msg, null);
    }

    /** 失败，自定义 code */
    public static <T> Result<T> fail(Integer code, String msg) {
        return new Result<>(code, msg, null);
    }

    public Integer getCode() {
        return code;
    }

    public void setCode(Integer code) {
        this.code = code;
    }

    public String getMsg() {
        return msg;
    }

    public void setMsg(String msg) {
        this.msg = msg;
    }

    public T getData() {
        return data;
    }

    public void setData(T data) {
        this.data = data;
    }
}
```

Controller 里这样用：

```java
@GetMapping("/list")
public Result<List<User>> list() {
    return Result.ok(userService.list());
}
```

如果嫌每个方法都写 try-catch 麻烦，后面可以再加一个 `@RestControllerAdvice` 全局异常处理器，把异常统一转成 `Result.fail(e.getMessage())`。本期不是必须的。

## 五、MyBatis-Plus 配置

### 5.1 application.yml

放在 `src/main/resources/application.yml`：

```yaml
server:
  port: 8080
  # 注意：这里不要配 context-path，路径前缀写在 Controller 的 @RequestMapping 里

spring:
  application:
    name: campus-errand
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/campus_errand?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: root
    password: 123456
  # 让返回给前端的日期是 "2024-05-20 12:00:00" 这种格式，而不是时间戳
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: GMT+8

mybatis-plus:
  configuration:
    # 关键配置：数据库下划线命名 自动映射成 Java 驼峰命名
    map-underscore-to-camel-case: true
    # 把执行的 SQL 打印到控制台，方便调试
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
  global-config:
    db-config:
      # 主键策略：跟随数据库的自增
      id-type: auto
    # 关闭启动时的 banner，看着清爽一点（要不要都行）
    banner: false
  # 如果后面要写 XML，把 XML 放在 resources/mapper 下
  mapper-locations: classpath*:/mapper/**/*.xml
  # 实体类所在包，写了以后 XML 里可以直接用 User 不用写全类名
  type-aliases-package: com.example.campus.entity
```

### 5.2 map-underscore-to-camel-case 是什么意思

数据库字段用下划线，Java 属性用驼峰，这个开关打开以后，MyBatis-Plus 自动帮你对应，**不用写 @TableField 注解**：

| 数据库字段 | Java 属性 |
| --- | --- |
| user_id | userId |
| create_time | createTime |
| update_time | updateTime |
| receiver_building | receiverBuilding |
| total_amount | totalAmount |
| order_no | orderNo |
| is_default | isDefault |
| goods_name | goodsName |

如果这个开关没打开（或者不小心写成了 false），查询结果里 `userId` 会一直是 null，而数据库里明明有值，这是最常见的新手问题。打开以后，只要实体类属性名和表字段名按上面规则对应，就能自动填充。

少数对不上的情况（比如 Java 里叫 `id` 而表里是 `user_id`），才需要手动加注解：

```java
@TableField("user_id")
private Long id;
```

### 5.3 实体类示例

```java
package com.example.campus.entity;

import com.baomidou.mybatisplus.annotation.IdType;
import com.baomidou.mybatisplus.annotation.TableId;
import com.baomidou.mybatisplus.annotation.TableName;

import java.math.BigDecimal;
import java.time.LocalDateTime;

@TableName("user")   // 表名是 user，和类名 User 只差大小写时可以省略
public class User {

    @TableId(type = IdType.AUTO)   // 主键自增
    private Long id;

    private String username;
    private String password;
    private String realName;
    private String nickname;
    private String phone;
    private String avatar;
    private String studentNo;
    private Integer role;
    private BigDecimal balance;
    private Integer status;
    private LocalDateTime createTime;
    private LocalDateTime updateTime;

    // 这里放 getter / setter，或者用 Lombok 的 @Data
}
```

用 Lombok 的话，类上加 `@Data` 就不用写一堆 getter/setter 了。pom.xml 里需要：

```xml
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-boot-starter</artifactId>
    <version>3.5.5</version>
</dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <optional>true</optional>
</dependency>
```

注意：MySQL 8 的驱动类是 `com.mysql.cj.jdbc.Driver`，连接地址一定要带 `serverTimezone=Asia/Shanghai`，否则日期可能差 8 小时。

## 六、包结构建议

基础包名假设是 `com.example.campus`（在 IDEA 里用 Spring Initializr 建项目时自己填的那个 Group + Artifact 改一下就行）。

```
com.example.campus
├── CampusErrandApplication.java    启动类，放在最外层包下
├── common                          公共类
│   ├── Result.java                 统一返回格式
│   ├── CorsConfig.java             跨域配置
│   └── GlobalExceptionHandler.java 全局异常处理（可选）
├── controller                      接收前端请求，只做参数校验和调用 service
│   ├── UserController.java
│   ├── AddressController.java
│   ├── ShopController.java
│   ├── GoodsController.java
│   ├── StationController.java
│   ├── CartController.java
│   ├── OrderController.java
│   ├── RiderController.java
│   └── AdminController.java
├── service                         业务接口
│   ├── UserService.java
│   ├── OrderService.java
│   └── ...
├── service/impl                    业务实现，写真正的逻辑
│   ├── UserServiceImpl.java
│   ├── OrderServiceImpl.java
│   └── ...
├── mapper                          继承 BaseMapper，一个表一个
│   ├── UserMapper.java
│   ├── OrderMapper.java
│   └── ...
├── entity                          和数据库表一一对应的类
│   ├── User.java
│   ├── Orders.java
│   └── ...
├── dto                             前端传过来的请求参数对象
│   ├── OrderCreateDTO.java
│   ├── CartAddDTO.java
│   └── ...
└── vo                              返回给前端的对象
    ├── OrderVO.java                订单 + 明细
    ├── RiderStatisticsVO.java      骑手统计
    └── AdminStatisticsVO.java      管理端统计
```

各层的分工，一句话记住：

| 包 | 干什么 | 不该干什么 |
| --- | --- | --- |
| controller | 接请求、校验参数、调 service、包成 Result 返回 | 不写 SQL，不写复杂业务判断 |
| service | 写业务逻辑、算金额、开事务、多次调 mapper | 不直接处理 HttpServletRequest |
| mapper | 继承 `BaseMapper<Entity>`，负责读写数据库 | 不写业务判断 |
| entity | 和表字段一一对应 | 不要在这里塞额外的展示字段 |
| dto | 接前端传进来的参数（比如下单请求） | 不要当返回值用 |
| vo | 返回给前端的组合数据（比如订单 + 明细列表） | 不要直接当入参 |

package 名里不要用 `service.impl` 这种带点的写法，要建成 `service` 包下面再建一个 `impl` 子包。

每个 Mapper 长这样，继承 `BaseMapper` 就有基础增删改查了：

```java
package com.example.campus.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.example.campus.entity.User;
import org.apache.ibatis.annotations.Mapper;

@Mapper
public interface UserMapper extends BaseMapper<User> {
}
```

启动类上要加 `@MapperScan`，不然会报找不到 Mapper：

```java
@SpringBootApplication
@MapperScan("com.example.campus.mapper")
public class CampusErrandApplication {
    public static void main(String[] args) {
        SpringApplication.run(CampusErrandApplication.class, args);
    }
}
```

## 七、关于登录：查表登录，不做 JWT 和拦截器

这一点非常重要，先看清楚再写代码：

1. **有登录接口，但没有 JWT、没有 Session、没有 Spring Security、没有拦截器**。登录就是拿用户名密码查一次 user 表，查到就把用户信息返回给前端。不要把登录拦截器加进来，加了前端所有请求都会 401。
2. **前端把登录成功的用户信息存在 localStorage 里**，之后调其它接口时通过参数把当前用户 ID 传过来，后端直接拿这个 userId 当"当前登录用户"用。
3. `POST /api/user/login` 要**真的校验密码**：按 username + password 查，查不到就返回 `code = 500`、`msg = "用户名或密码错误"`，不需要返回 token。
4. `POST /api/user/register` 往 user 表插一条记录，role 固定 1（顾客）；用户名重复要返回 `code = 500`、`msg = "用户名已存在"`。
5. 传参方式有两种，看接口怎么定义：
   - 查询参数（GET 请求）：`GET /api/address/list?userId=1`
   - 请求体字段（POST/PUT 请求）：`{ "userId": 1, "shopId": 3, ... }`
6. 权限也不校验。比如 `/api/admin/**` 下面的接口，谁调都能成功，不需要判断 role 是不是 3。前端只是根据 role 决定显示哪些菜单、给不给进某些页面，这是示例项目有意为之，方便调试。

Controller 里怎么拿这个 userId：

```java
// GET 请求：用 @RequestParam
@GetMapping("/list")
public Result<List<Address>> list(@RequestParam Long userId) {
    return Result.ok(addressService.listByUserId(userId));
}

// POST 请求：放在 DTO 里，加 @RequestBody
@PostMapping("/create")
public Result<Orders> create(@RequestBody OrderCreateDTO dto) {
    // dto.getUserId() 就是当前用户
    return Result.ok(orderService.createOrder(dto));
}
```

前端联调时，先用 `xiaoming / 123456` 登录（拿到 `id = 1`），后面下单、查订单就都用这个 id；测骑手功能用 `dali / 123456` 登录（user.id = 2，对应的 rider.id = 1）；测管理端用 `wanglaoshi / 123456` 登录。

## 八、从零开始写后端的步骤

按这个顺序做，每一步都能单独验证，不容易卡住。

| 步骤 | 做什么 | 怎么验证 |
| --- | --- | --- |
| 1 | 建 SpringBoot 项目，勾选 Spring Web、MySQL Driver、Lombok | 启动成功，控制台看到 Tomcat started on port 8080 |
| 2 | pom.xml 加上 `mybatis-plus-boot-starter` | Maven 依赖不报红 |
| 3 | 用 Navicat 执行 `sql/campus_errand.sql`，确认 13 张表和数据都在 | 执行 `SELECT COUNT(*) FROM goods;` 应该返回 12 |
| 4 | 写 `application.yml`，先把 `server.port` 和 `datasource` 配好 | 启动不报数据库连接错误 |
| 5 | 写 `common/Result.java` 和 `common/CorsConfig.java` | 这两个类能编译通过 |
| 6 | 启动类加 `@MapperScan("com.example.campus.mapper")` | 启动时没有 mapper 相关警告 |
| 7 | 建包：controller / service / service/impl / mapper / entity / dto / vo / common | 目录结构对得上第六节 |
| 8 | 先写 `User` 实体 + `UserMapper` + `UserService` + `UserServiceImpl` + `UserController`，只做 `GET /api/user/list` | 浏览器打开 `http://localhost:8080/api/user/list`，能看到 3 个用户的 JSON |
| 9 | 按同样的套路把 shop、goods、goods_category、express_station 四个查询接口写完 | 数据库里有几条，接口就返回几条 |
| 10 | 写 address 和 cart 的增删改查（购物车注意先查后改） | 用 Postman 或接口文档调试页测一遍 |
| 11 | 写 `OrderCreateDTO` 和订单创建逻辑：生成订单号、算总金额、插 orders、插 order_item、插 order_status_log，整个方法加 `@Transactional` | 下一单，三张表都有新数据，金额算得对 |
| 12 | 写订单列表、订单详情（订单 + items）、骑手接单、改状态、取消 | 挨个测一遍，看 status 和对应时间字段有没有一起变 |
| 13 | 写骑手大厅、骑手统计、管理端统计和商品/店铺管理接口 | 管理端统计数字和数据库对得上 |
| 14 | 前端把 `.env.development` 的 `VITE_USE_MOCK` 改成 false（代理已经配好，不用动），重启后开始联调 | 页面上的数据来自数据库，改数据库能看到变化 |

几个流程上的提醒：

- **配置和工具类先写**。Result 和 CorsConfig 没写好就开始写业务，后面每个 Controller 都要返工。
- **表对应的实体类建议一次性全建出来**，13 个实体类，用 IDEA 的 Database 工具可以自动生成，比手敲快也不容易错。
- **订单创建是唯一需要开事务的地方**，`orders`、`order_item`、`order_status_log` 三张表要么全插成功要么全不插。在 Service 实现类的方法上加 `@Transactional` 注解即可。
- **金额一律用 BigDecimal**，不要用 double。`0.1 + 0.2` 用 double 算出来不是 0.3，钱算错就麻烦了。

## 九、常见问题对照表

| 现象 | 多半是什么原因 |
| --- | --- |
| 前端请求 404 | Controller 上少了 `/api` 前缀，或者 `context-path` 多配了一层 |
| 前端请求 500，控制台报数据库连接失败 | application.yml 里的密码不对，或者 MySQL 服务没启动 |
| 返回的 JSON 里字段全是 null | `map-underscore-to-camel-case` 没打开 |
| 报错 `Unknown column 'user_name' in 'field list'` | 实体类属性名和表字段名对不上，检查驼峰转换规则 |
| 日期差 8 小时 | JDBC 地址缺 `serverTimezone=Asia/Shanghai` |
| 报 `Invalid bound statement (not found)` | Mapper 接口没加 `@Mapper`，或者启动类没加 `@MapperScan` |
| 加购物车报唯一索引冲突 `uk_user_goods` | 没有先查再改，直接 insert 了重复的 userId + goodsId |
| 浏览器报 CORS 错误 | CorsConfig 没生效，检查包路径是否在启动类的同级或子包下 |
| 跨域配置启动就报错 | `allowedOrigins("*")` 和 `allowCredentials(true)` 同时用了，改成 `allowedOriginPatterns("*")` |
