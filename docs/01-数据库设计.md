### 为什么不加外键约束

外键（FOREIGN KEY）会在数据库层面强制检查"这条数据引用的那条数据必须存在"。听起来很好，但对课程作业不友好：

1. 插入顺序被卡死。必须先插 user，再插 orders，再插 order_item，顺序错一步就报错。做演示数据、写单元测试的时候特别烦。
2. 删数据也麻烦。想删一个用户，得先删他的地址、订单、购物车，不然删不掉。
3. 报错信息不直观。学生看到 `Cannot add or update a child row` 往往不知道是自己漏插了哪条数据。
4. 关联关系我们已经写在 Java 代码里了，查询时自己写条件就行，不需要数据库再管一遍。

所以本项目所有关联字段（比如 orders.user_id、order_item.order_id）都只是普通的 BIGINT 字段，不加外键。**代价是：数据正确性要靠后端代码自己保证。**比如创建订单时，要在 Service 里自己检查 userId 对应的用户存在、goodsId 对应的商品存在。

必要的索引我们还是加了（唯一索引 + 普通索引），这样查询速度够用。

三大业务的存储方式：

- **代取快递**：orders 里 order_type = 1，用到 station_id、pickup_code、express_company、package_size、package_weight，shop_id 为空，没有 order_item。
- **校园外卖**：orders 里 order_type = 2，用到 shop_id，有 order_item，station_id 为空。
- **小卖部**：orders 里 order_type = 3，用到 shop_id，有 order_item，station_id 为空。

也就是说，**一张 orders 表存三种订单**，用不到的那些字段留空（NULL）就行。

## 四、表之间的关系

一句话版本：**user 是中心，所有业务数据最后都能追到某个 user 和某张 orders 上。**

```
user（用户）
 ├─ 1 : n ─ address        一个用户有多个收货地址
 ├─ 1 : 1 ─ rider          骑手本身也是用户，多一张骑手信息表
 ├─ 1 : n ─ cart           一个用户购物车里有多个商品
 └─ 1 : n ─ orders         一个用户下过多张订单
              │
              ├─ n : 1 ─ user     下单人        （orders.user_id    → user.id）
              ├─ n : 1 ─ rider    接单骑手      （orders.rider_id   → rider.id，可为空）
              ├─ n : 1 ─ shop     下单店铺      （orders.shop_id    → shop.id，可为空）
              ├─ n : 1 ─ station  取件驿站      （orders.station_id → express_station.id，可为空）
              ├─ 1 : n ─ order_item        订单买了哪些商品
              ├─ 1 : n ─ order_status_log  订单状态变化记录
              └─ 1 : 1 ─ order_review      订单评价（预留）

shop（店铺）
 └─ 1 : n ─ goods_category（商品分类） ─ 1 : n ─ goods（商品）
                                                │
cart（购物车） ─ n : 1 ─ goods ──────────────────┘
```

几条容易绕晕的关系，单独说明：

| 关系 | 怎么关联 | 注意点 |
| --- | --- | --- |
| 订单 → 下单人 | orders.user_id = user.id | user_id 一定不为空 |
| 订单 → 骑手 | orders.rider_id = rider.id | 用 rider.id，不是 user.id；待接单时是 NULL |
| 订单 → 店铺 | orders.shop_id = shop.id | 只有外卖和小卖部单有值 |
| 订单 → 驿站 | orders.station_id = express_station.id | 只有代取快递单有值 |
| 订单 → 明细 | order_item.order_id = orders.id | 一张订单可以有多条明细 |
| 订单 → 流水 | order_status_log.order_id = orders.id | 一张订单可以有多条流水 |
| 订单 → 评价 | order_review.order_id = orders.id | 一对一，order_id 上有唯一索引 |
| 店铺 → 分类 | goods_category.shop_id = shop.id | shop_id = 0 表示平台通用分类 |
| 分类 → 商品 | goods.category_id = goods_category.id | 商品的 shop_id 要和分类的 shop_id 对得上 |
| 购物车 → 商品 | cart.goods_id = goods.id | 同一用户同一商品只能有一行 |
